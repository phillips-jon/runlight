Add Runlight analytics to this app. Runlight is a package that runs inside the app. It stores visits in the app's own database and serves its dashboard at /runlight. The docs are at https://runlight.sh/docs/, where each page is also available as Markdown at index.md, and https://runlight.sh/llms.txt lists every page.

The steps below are for JavaScript and TypeScript apps, which use the npm package @runlight/sdk. Runlight is also written for other languages, with the same dashboard and the same tables. If this app is in one of them, use its package and follow its page instead, which has the install, the routes for each framework, the scheduled check, and the AI agent middleware.

- PHP (Laravel, Symfony, or plain PHP): composer require runlight/runlight, then https://runlight.sh/docs/php/index.md
- Python (Django, Flask, FastAPI, or any WSGI or ASGI app): pip install runlight, then https://runlight.sh/docs/python/index.md
- Rails: bundle add runlight and bin/rails generate runlight:install, then https://runlight.sh/docs/rails/index.md
- Ruby (Sinatra, Hanami, Roda, or any other Rack app): bundle add runlight sqlite3, then https://runlight.sh/docs/ruby/index.md
- Go (net/http, chi, or Echo): go get runlight.sh/go, then https://runlight.sh/docs/go/index.md
- Java (the JDK's server, a servlet container, or Spring Boot): sh.runlight:runlight from Maven Central, then https://runlight.sh/docs/java/index.md
- .NET (ASP.NET Core): dotnet add package Runlight.AspNetCore, then https://runlight.sh/docs/dotnet/index.md
- Elixir (Phoenix or Plug): {:runlight, "~> 0.0"} in mix.exs, then https://runlight.sh/docs/elixir/index.md
- Rust (axum, hyper, or tower): the runlight and runlight-sqlx crates, then https://runlight.sh/docs/rust/index.md

A WordPress, Drupal, or Craft CMS site takes a plugin that connects it to a Runlight running elsewhere, as https://runlight.sh/docs/wordpress/index.md, https://runlight.sh/docs/drupal/index.md, and https://runlight.sh/docs/craft/index.md describe.

1. Install the package with npm install @runlight/sdk better-sqlite3
   (For Postgres, run npm install @runlight/sdk pg and use postgres({ url: process.env.DATABASE_URL }) from "@runlight/sdk/postgres".
    On Bun use bunSqlite from "@runlight/sdk/bun", on Cloudflare Workers use d1 from "@runlight/sdk/d1", and for Turso use libsql from "@runlight/sdk/libsql".)

2. Create lib/runlight.ts (or the project's equivalent).

   import { runlight } from "@runlight/sdk";
   import { sqlite } from "@runlight/sdk/sqlite";

   export const rl = runlight({
     store: sqlite({ path: "./data/runlight.db" }),
     site: { name: "<site name>", hostnames: ["<production hostname>"], timezone: "<IANA timezone>" },
   });

   Make sure ./data is gitignored if it is new.

3. Mount the routes under /runlight, for every HTTP method.
   For the Next.js App Router, create app/runlight/[[...path]]/route.ts with this content.
     import { rl } from "@/lib/runlight";
     export const { GET, POST, PUT, PATCH, DELETE, OPTIONS } = rl.routes();
   For Express or Node, use app.use(toNodeHandler(rl.routes().handler)) with toNodeHandler from "@runlight/sdk/node".
   For any framework with web Request objects, pass the request to rl.routes().handler and return its Response.
   The install guide at https://runlight.sh/docs/install/ covers other frameworks.

4. Add <script defer src="/runlight/s.js"></script> to every page, before </head> (the root layout in Next.js).

5. Add RUNLIGHT_TOKEN (a long random string) and CRON_SECRET to the environment and to .env.example. Do not commit real values.

6. Schedule GET or POST /runlight/api/check hourly with "Authorization: Bearer $CRON_SECRET". On Vercel, add { "crons": [{ "path": "/runlight/api/check", "schedule": "0 * * * *" }] } to vercel.json.

7. Optionally, count AI agents reading pages by calling rl.observe(request) without awaiting it in middleware (proxy.ts in Next.js 16+, middleware.ts before).

Then tell the user to open /runlight/?token=<their RUNLIGHT_TOKEN> to sign in. Runlight sets no cookies and stores no personal data, so do not add cookie banners for it.
